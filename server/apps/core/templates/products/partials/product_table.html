{% comment %} Product Inventory table — Products & Pricing page. Edit-then-confirm flow: - All fields (name, variation, price) are read-only by default. - The user clicks "Edit" → ``editing`` flips to true and non-default product fields become editable (the button switches to "Save Changes" + "Cancel"). All per-product state lives on the root Alpine scope (no nested x-data) so ``:readonly="!editing"`` is fully reactive. - The user edits one or more fields; dirty values are tracked centrally in ``changedNames``, ``changedVariations``, and ``changedPrices`` (keyed by product key). - Clicking "Save Changes" opens the PIN modal. The PIN is verified via POST to ``{% url 'products:verify_pin' %}``. On success the edits are committed (originals snap to the new value) and the table returns to read-only. - "Cancel" exits edit mode and reverts all inputs to their originals. - The Active toggle is disabled unless edit mode is active. Inline add flow (no separate page or modal): - Clicking "Add Product" enters edit mode (if not already) and appends an empty draft row at the bottom of the table. The draft row has editable Name, Variation, and Price inputs plus a remove (×) button. - Multiple draft rows can be added in a single edit session. - Clicking "Save Changes" sends the drafts as a ``creates`` array to the save endpoint alongside any edits/deletes. On success, each created product is promoted to a read-only row (with a "New" badge) using the real DB id returned by the server. Drafts are cleared. - Clicking "Cancel" discards all draft rows. Default products (``is_default=True``): - All fields are permanently locked (read-only, never editable). - No delete button — default products cannot be removed. - A lock icon signals the protected status. Non-default products (``is_default=False``): - Fields are read-only until "Edit" is clicked, then editable. - In edit mode, a Delete button marks the row with a strikethrough (pending deletion). The actual deletion is committed when "Save Changes" is clicked and the PIN is verified. Clicking the (now "undo") button again reverts the pending deletion. - When not in edit mode, an Activate or Deactivate button is shown instead (based on the product's current active status). Expects context: - products: list of { id, name, variation, unit_price, is_active, is_default, row_class, name_class, action_activate } - active_count, default_count, total_count {% endcomment %}
